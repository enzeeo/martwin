Real in production: the candidate list (GET /api/catalog, per selected feature), which ones are kept (the done event), and their order. The model writes its answer feature by feature: comparisons, then filters, each group alphabetical. That is the order the replay follows. It keeps 1 to 3 options per feature.
Replayed, not live: today the whole answer arrives at once, so the per-feature pace is compressed. If the backend streamed the model's output, the same animation could run at the real pace.
Decoration only: the pulsing and rewiring while the model works. Both are random and uniform, so they never hint at the answer.
